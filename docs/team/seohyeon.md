## 회의 전 (11/10까지, 단톡 공유)

### 최신 로컬 재검토안 (2026-11-11)

- 사용자 가정: `avg_days`=월간 접속 횟수, `avg_daily_time`=일간 접속 횟수. 이 가정은 이번 로컬 초안에 적용하며, 제공처 공식 정의 확인을 대신하지 않는다.
- 1번: 최대값=1 비교표·Fisher/FCQ·월별 민감도 분석은 완료했다. 이번에는 문항 범위까지 검토해 **우선 12개(게임 조건부)+보완 2개**로 연결했다. 팀 확정 전 재검토안이다.
- 2번: **월간 대략 정수 횟수 / 지난 7일 총 정수 횟수**의 대안으로 갱신했다. 횟수에는 31회·7회 상한을 두지 않는다. 같은 사용자에게 두 대안을 모두 묻지 않는다.
- 3번: 새 우선 12개·월간 응답·최대값 기준으로 방법을 다시 비교했다. 실제 설정은 비활성 상태로 유지하며 기존 서비스 설정 파일은 수정하지 않았다.
- 통합 문서: `data/processed/real/seohyun/revised_123/revised_123.md`. 선정 근거는 같은 폴더의 `selected_candidates.csv`, 문항 계약 초안은 `questions.draft.json`.
- 2026-11-12 사용자 요청으로 `config/codebook.yaml`·`config/similarity.yaml`에 최종 회의 자료의 월간 횟수·MaxAbs·Fisher·FCQ·코사인 계약을 작성했다. 유사도는 비활성이며, 기존 Python의 일수 검사·제외 정책과 Java의 횟수 입력·정규화·코사인은 구현이 필요하다. 차현우에게 코드북·정제 계약, 신진용에게 설문·유사도 계약을 인계한다. 앞의 ‘설정 미수정’ 문장은 11/11 산출물 당시의 기록이다.
- 아래의 일수형 문항·기존 14개 문항 기록은 이전 설계 이력이다. 이번 횟수 가정에 그대로 적용하지 않는다. 접속 1회·평균 분모·주간 비교 조건·인지 면담은 확인이 필요하다.

로컬 실행 순서와 검토표 작성법: [서현의 회의 전 로컬 작업 안내](../analysis/seohyeon-local-guide.md).
현재 CSV 분석부터 문항·유사도·유형·5분 요약 초안 생성까지 담당자가 직접 실행한다.
